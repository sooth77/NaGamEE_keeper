# 평가 방법과 결과

## 1. 평가 데이터

| 평가셋 | 질문 | 정답 기준 | 용도 |
|---|---:|---|---|
| 공개 V2 | 100 | V2 규약집 | 공식 비교 |
| 공개 V3 | 같은 100 | V3 규약집, 정답 7개 변경 | 공식 비교, 개정 대응 |
| 처음 보는 사례 | 100 | V3 규약집 | 일반화 확인 (나감이만 실행) |
| 팀 문항 | 16 + 48 | V2 / V3 | 개발 중 회귀 확인 |
| 강점 문항 | 8 + 40 | V2 / V3 | 개발 중 회귀 확인 (V3의 8개는 계산기 오작동 확인용) |

- 공개 V2·V3는 같은 질문이고, 개정으로 정답이 바뀐 7문항이 **개정 대응** 지표가 돼요.
- 팀·강점 문항은 나감이 코드를 고칠 때 본 문항이라 일반 성능으로 보고하지 않아요.
- 운영진 평가셋과 정답은 이 저장소에 넣지 않았어요. `evaluation/questions/`에는 팀이 만든 질문만 있어요.

## 2. 실행 조건

## 3. 채점

```text
답변 936개 (3개 시스템 × 312개)
├─ 오작동 확인용 24개       정답 점수에서 제외
└─ 채점 대상 912개
   ├─ 코드가 확정 540개     예/아니오, 객관식, 숫자, 인용, 시간
   └─ GPT Sol 채점 372개    코드가 판단할 수 없는 서술형
```

서술형은 G-Eval 방식으로 4개 항목을 1~5점 매겼어요. 어느 시스템의 답인지는 숨기고 순서를 섞었어요.

| 항목 | 배점 | 5점 | 1점 |
|---|---:|---|---|
| 결론 정확성 | 40 | 결론과 수치 모두 맞음 | 결론이 틀림 |
| 판본·기준일 | 25 | 둘 다 맞게 명시 | 틀린 판본 적용 |
| 근거 충실성 | 25 | 필요한 조항·표 모두 인용 | 없거나 지어냄 |
| 다음 행동 | 10 | 규정에 맞고 구체적 | 없거나 규정과 어긋남 |

| 판정 기준 | 정의 |
|---|---|
| **엄격 (대표 점수)** | 코드 판정 + Sol 최종 판정 + 3인 검수 반영 |
| 참고 | 결론 점수 3점 이상(결론은 맞고 일부 조건만 빠짐)도 정답. 틀린 계산과 결론은 오답 유지 |

참고 기준은 결과를 본 뒤 정한 기준이라 대표 점수로 쓰지 않아요.

### 채점 신뢰도

| 확인 | 결과 |
|---|---|

### 통계적으로 확인된 것과 아닌 것

- 32B와 나감이의 정확도 차이 16%p는 유의해요 (짝 비교 p < 0.001).
- 나감이와 4B 단독의 차이 3.5%p는 **아직 확정할 수 없어요** (p = 0.065).
- 개정 대응은 7쌍뿐이라 표본이 작아요.

## 5. 어떤 문제가 어려웠나

공개 100문항을 세 시스템이 V2·V3로 풀어 문항당 6번 채점했어요. 59문항은 6번 모두 정답, 14문항은 1번 이하였어요.

| 난이도를 가른 요인 | 나감이 정답률 (공개) |
|---|---:|
| 필요한 근거 1쪽 | 86% |
| 필요한 근거 2쪽 | 72% |
| 필요한 근거 3쪽 | 50% |
| 필요한 근거 4쪽 이상 | 33% |
| 경과조치(부칙 53~58쪽) 필요 | 56% |
| 경과조치 필요 없음 | 73% |

가장 어려운 14문항은 **여러 규칙 종합 서술 5개, 정보 부족 시 되묻기 4개, 여러 한도 결합 3개, 과거 사건 판본 선택 2개**였어요.
