# 나감이 · 신혼 생활 지킴이

> 나 감도 아니고 배도 아닌, **나감이!**
> 감 놔라 배 놔라 하지 않고, 공동생활 규약대로만 판정해 드립니다.

## 1. 프로젝트 소개

신혼부부 나미와 감석이의 **공동생활 규약집**을 근거로, 지출·가사·손님·여행·투자 같은 생활 질문에 판정과 근거를 답하는 챗봇이에요.
DLthon 2 「신혼생활 운영위원회」 과제로 3인 팀이 만들었어요.

규약집은 운영 중에 **V1 → V2 → V3로 개정**돼요. 그래서 나감이의 핵심 과제는 단순 검색이 아니라
**사건 날짜에 맞는 판본의 기준을 골라 정확히 계산하고, 근거 조항과 표를 함께 제시하는 것**이었어요.

| 항목 | 내용 |
|---|---|
| **답변 모델** | Qwen3-32B를 교사로 지식 증류한 **Qwen3-4B 학생 모델**, AWQ W4A16 양자화 (2.67GB) |
| **검색** | KURE-v3 임베딩 + KURE-Reranker-nano, Qdrant |
| **흐름 제어** | LangGraph 9단계. 날짜·판본·계산·검증은 코드가, 문맥 이해와 설명은 4B가 담당 |
| **화면** | Streamlit, 날짜가 빠지면 되묻고 판정 결과를 하트 표정으로 표시 |
| **핵심 성과** | 모델 파일 약 1/25, 개정 대응 7/7, 첫 토큰 100% 1초 이내, 지어낸 인용 0건 |

## 2. 모델 설계

### 2-1. 모델 선정

| 후보 | 크기 | 결과 |
|---|---|---|
| Gemma 4 | 31B | 후보 |
| EXAONE 4.0 | 32B | 후보 |
| **Qwen3** | **32B** | **최종 선택** |

Qwen3를 고른 이유는 세 가지예요.

- **효율성:** 같은 어텐션 구조를 반복하고 GQA를 써서, 긴 질문에서도 KV 캐시와 속도 부담이 작아요.
- **성능:** 긴 문맥에서 조항과 표의 세부 수치를 놓치지 않았어요.
- **선례:** 공개된 Qwen3 프루닝·경량화 사례가 있어 문제가 생겨도 참고할 수 있었어요.

### 2-2. 경량화 파이프라인

```text
Qwen3-32B (교사, 65.5GB)
      │  지식 증류: 규약 판정과 맥락 파악을 학생에게 전달
      ▼
Qwen3-4B (학생)
      │  보강 학습: 증류 후 부족해진 부분을 대화셋 964개로 학습
      ▼
AWQ W4A16 양자화 (llm-compressor)
      │  가중치 4bit · 활성값 16bit · 비대칭 · 그룹 128 · lm_head 제외
      ▼
최종 모델 2.67GB (교사 대비 약 1/25)
```

처음에는 32B를 구조적 프루닝으로 줄이는 방식도 시도했고, 최종 모델은 **증류 후 양자화** 방식으로 만들었어요.

### 2-3. 최종 모델 사양

| 항목 | 값 |
|---|---|
| 구조 | `Qwen3ForCausalLM`, 디코더 36층 |
| 히든 크기 / FFN 크기 | 2,560 / 9,728 |
| 어텐션 | 쿼리 헤드 32개, KV 헤드 8개 (GQA) |
| 어휘 수 | 151,936 |
| 양자화 | AWQ W4A16 비대칭, 그룹 크기 128, `compressed-tensors` 형식 |
| 생성 설정 | 온도 0, 최대 1,536토큰, 생각 모드 끔 |
| 모델 파일 | 2.67GB |
| 최대 GPU 메모리 | 8.45GiB (평가 실행 기록) |

모델 가중치는 용량 때문에 이 저장소에 넣지 않았어요. 설정 파일과 양자화 레시피는 [`model/`](model/)에,
자세한 설명은 [`model/MODEL_CARD.md`](model/MODEL_CARD.md)에 있어요.

## 3. 시스템 아키텍처

**코드는 규칙을, 4B는 문맥을** 맡는 구조예요. 규칙이 분명한 판단은 코드가 먼저 끝내서 모델 호출을 줄였어요.

```text
[사용자] ── Streamlit 화면 (V2 / V3 규약집 선택)
                 │
                 ▼
 ① 질문 정리   잡담·이모티콘·전각 숫자 제거, 출력 형식 지시 추출
                 ▼
 ② 코드 판별   어떤 규칙 항목인지, 판본이 바뀌는 항목인지 확인
                 ▼
 ③ 날짜 확인   판본을 정할 날짜가 없으면 멈추고 되묻기 (interrupt)
                 ▼
 ④ 조항 검색   KURE-v3 + 리랭커, 과거 사건이면 날짜별 판본으로 검색
                 ▼
 ⑤ 판본 계산   항목별 기준일 → 적용 판본 → 기준값으로 코드 계산
                 │
        ┌────────┴────────┐
   코드로 확정          확정 못 함
        │                 │
        │          ⑥ 근거 보강 + ⑦ 4B 답변 (바로 스트리밍)
        └────────┬────────┘
                 ▼
 ⑧ 최종 검사   다른 판본 값 혼입, 답 잘림, 인용 확인 → 필요하면 4B가 1회 재작성
                 ▼
 ⑨ 답변 형식   판정 · 근거 조항과 표 · 다음 행동 + 생활 명언
```

### 판본을 섞지 않는 방법

규약집은 **문서 판본**(지금 보고 있는 규약집이 V2인지 V3인지)과 **적용 판본**(사건에 어느 시기 기준을 쓰는지)이 달라요.
V3 규약집을 쓰더라도 9월 사건에는 V1 기준을 적용해야 해요.

- **판본표:** 값이 바뀌는 19개 항목의 판본별 기준값과 **항목별 기준일**을 [`data/versions_v3.json`](data/versions_v3.json)에 정리했어요.
- **코드가 결정:** `rules/versions.py`가 기준일로 판본을 고르고, 경계 시각(10월 1일 00시, 12월 1일 00시)은 새 판본으로 처리해요.
- **되묻기:** 기준일을 알 수 없으면 값을 단정하지 않고 "추가 확인"으로 답해요.
- **사후 검사:** `rules/guard.py`가 답에 다른 판본의 기준값이 섞였는지 확인해요.

## 5. 결과

### 5-1. 공개 평가셋 (V2 100문항 + V3 100문항)

세 시스템이 **같은 질문, 같은 검색 근거, 같은 지시문**으로 답했고, 같은 채점 기준을 적용했어요.

| 지표 | 32B | 4B 단독 | **나감이** |
|---|---:|---:|---:|
| 판정 정확도 (엄격 기준) | **85.5%** | 66.0% | 69.5% |
| 개정 대응 (V2·V3 모두 정답) | 5/7 | 3/7 | **7/7** |
| 정답 + 조항·표 모두 인용 | 44 | 54 | **56** |
| 지어낸 인용 | 0 | 3 | **0** |
| 모델 파일 | 65.5GB | 2.67GB | **2.67GB** |
| 최대 GPU 메모리 | 24.8GiB | 8.46GiB | **8.45GiB** |
| 첫 토큰 (V3 중앙값) | 0.84초 | 0.21초 | **0.22초** |
| 결론까지 (V3 중앙값) | 3.37초 | 2.65초 | **2.43초** |
| 답변 완료 (V3 중앙값) | **4.73초** | 6.38초 | 5.59초 |

- 나감이는 모델을 약 1/25로 줄이고 **32B 정확도의 약 81%**를 유지했어요.
- **개정 대응, 근거 인용, 첫 응답 속도**는 32B보다 좋았어요.
- 결론이 맞고 일부 조건만 빠진 답을 인정하는 **참고 기준**에서는 32B 86.5%, 4B 68.5%, 나감이 73.0%예요.

| 문제 유형 (엄격 기준) | 32B | 4B | 나감이 |
|---|---:|---:|---:|
| 예/아니오 | 100% | 96% | 96% |
| 숫자 계산 | 98% | 84% | 84% |
| 객관식 | 100% | 73% | 73% |
| 서술형 | 84% | 58% | 67% |
| 여러 항목 서술 | 30% | 20% | 15% |

## 6. 실행 방법

GPU 환경(Colab 등)을 기준으로 해요.

```bash
cd NaGamEE_keeper
pip install -r requirements.txt
```

1. 운영진이 배포한 규약집 조각 `rulebook_V2.jsonl`, `rulebook_V3.jsonl`을 `data/`에 넣어요. ([`data/README.md`](data/README.md))
2. 최종 4B AWQ 모델 폴더 경로를 지정하고 화면을 실행해요.

```bash
NAGAMI_M4=/path/to/final_student_4b_awq_asym streamlit run app/streamlit_app.py
```

평가는 이렇게 실행해요.

```bash
python evaluation/run_eval.py prepare --out results --work /content/work
python evaluation/run_eval.py run --out results --m4 /path/to/4b --m32 /path/to/qwen3-32b
```

## 8. 팀과 출처

| 담당 | 역할 |
|---|---|
| A | 문서 처리, 판본 관리, 검색기 (`retriever/`) |
| B | 모델 선정, 지식 증류, 양자화 |
| C | LangGraph, 화면, 평가 자동화 (`app/`, `graph/`, `rules/`, `evaluation/`) |

- 기반 모델: [Qwen3](https://huggingface.co/Qwen) (Apache 2.0)
- 검색 모델: [nlpai-lab/KURE-v3](https://huggingface.co/nlpai-lab/KURE-v3), [nlpai-lab/KURE-Reranker-nano](https://huggingface.co/nlpai-lab/KURE-Reranker-nano)
- 공동생활 규약집과 평가셋은 과제 운영진이 제공한 자료라 이 저장소에 포함하지 않았어요.
